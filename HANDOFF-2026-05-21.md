# Rosey — handoff (2026-05-21)

Context for the next chat. This session built **Rosey Voice** — a realtime voice
interface for the household assistant — and made household memory **shared across
every channel**. Written ahead of the OpenAI Voice Hack Night (May 27).

## TL;DR

- Built **`voice-pwa` branch**: an installable PWA at **rosey.family/voice** that
  opens a WebRTC realtime session to **`gpt-realtime-2`** and talks to Rosey.
- Rosey's household tools are exposed to the realtime session as a **remote MCP
  server**, now **co-located inside the `rosey` engine app** reading the same
  `/data/memories` the Telegram/WhatsApp bot uses → **one shared household memory
  across all channels**. Add a reminder by text on WhatsApp, retrieve it by voice
  seconds later. This is confirmed working end-to-end.
- Runs on a **$55 Samsung Galaxy A16 5G (Tracfone)** as a tap-to-talk counter
  appliance — an open-source Alexa replacement.
- **Unconfirmed:** whether the latest lifecycle fix (`8ab028b`) makes "what are my
  reminders for tomorrow" read cleanly. Needs a website redeploy + retest.
- Wake-word ("Hey Rosey") is **not** live — Picovoice's console is gated behind
  commercial-use approval. Default is **tap-to-talk**; wake engine is swappable.

## Architecture (voice path)

```
$55 Android phone (Chrome PWA, plugged in, screen on)
  rosey.family/voice  (static, Cloudflare)
    │  tap orb → getUserMedia (echoCancellation on)
    ▼
  POST rosey-voice-token.fly.dev/session   → mints ephemeral OpenAI client secret
    │  (OPENAI_API_KEY stays server-side)
    ▼
  WebRTC → gpt-realtime-2  (speech-to-speech)
    │  session.update attaches a remote MCP server:
    │     server_url = https://rosey.fly.dev/mcp   (standard 443!)
    ▼
  OpenAI backend → rosey.fly.dev/mcp  (co-located mcp_server.py, internal :8089)
    │  reads/writes /data/memories  ← SAME volume as the Telegram/WhatsApp bot
    ▼
  one shared household memory (groceries/list.md, reminders.md, household.md, …)
```

Telegram/WhatsApp/voice all read+write the **same** files. That's the core innovation.

## Key config / facts

- **Realtime model:** `gpt-realtime-2` (speech-to-speech, WebRTC).
- **`CONFIG.WAKE_ENGINE`** in `website/voice/app.js`: `"tap"` (default), `"webspeech"`
  (works now but streams audio to Google — privacy caveat), `"porcupine"` (on-device,
  needs Picovoice key + `Rosey.ppn` in `website/voice/models/`).
- **`CONFIG.SESSION_ENDPOINT`** = `https://rosey-voice-token.fly.dev/session`.
- **`CONFIG.MCP_SERVER_URL`** = `https://rosey.fly.dev/mcp` (co-located, shared mem).
- MCP tools: `list_memory_files`, `read_memory_file`, `get_household`,
  `list_grocery_items`, `add_grocery_item`, `list_reminders`, `add_reminder`,
  `remember`. All auto-run (no approval) for a smooth hands-free demo.
- **Realtime API gotchas learned:** ephemeral key is at top-level `value`;
  `turn_detection` lives under `session.audio.input`; set `interrupt_response:false`
  + mic `echoCancellation:true` or Rosey interrupts herself; OpenAI's realtime MCP
  client **only connects on standard 443** (refused :8443 silently — hence the swap).

## Known gotchas

- **OpenAI realtime MCP requires standard 443** — non-standard ports are refused
  silently (no request reaches the server; surfaces as `mcp_list_tools.failed`).
- **Port-swap side effects:** Meta WhatsApp **Cloud API** webhooks and **Alexa** skill
  endpoints require 443 (now MCP's). Fine because WhatsApp is via Baileys (outbound);
  if Cloud API is ever needed, switch to path-routing on 443 instead of the swap.
- **Echo:** without `echoCancellation` + `interrupt_response:false`, Rosey hears her own
  voice and cuts off mid-reply. Headphones eliminate it entirely (best for demo).
- **Tool round-trip lifecycle:** tool questions = 2 responses (preamble+call, then the
  answer); the follow-up/sleep timer must be cleared on `response.created` and
  `mcp_call.in_progress` or it ends the session before the answer (fixed in `8ab028b`).
- **Git in the sandbox** can't unlink `.git/*.lock`; commits used a rename workaround,
  leaving `.git/*.cleared.*`/`.stale.*` files to clean up locally.
- **PII redaction (`redact.py`)** runs in the engine for the LLM text path, but the
  voice path sends raw audio straight to OpenAI — redaction can't touch that. Privacy
  levers for voice = ZDR + safety identifiers + least-privilege MCP, not redaction.

## Bug 2 (designed, not built): multi-image WhatsApp coalescing

WhatsApp sends N images as N separate `messages.upsert` events (caption usually on
the last). Today only the captioned one passes the group gate; the rest drop. Fix =
buffer media-only siblings ~3s keyed by `(sender_jid, chat_jid)` and bundle them with
the captioned/text-follow-up message into one agent call. Full design discussed; lives
in `whatsapp_handler.py` + a new `whatsapp_bundle.py`. (The baileys @-mention-on-caption
half-fix `84b2155` is already on `main`.)
